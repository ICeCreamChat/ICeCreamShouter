# ICeCream Shouter 完整部署与使用手册

这份手册按第一次接触部署工具的用户编写。你需要准备一台可联网的 Windows 10/11 电脑完成部署，以及一个你自己控制的 Cloudflare 账号。学校每间教室只需要复制同一个 EXE，再分别绑定班级。

## 一、你需要准备的东西

1. 一个常用邮箱，用来注册 Cloudflare 免费账号。
2. 一台能访问互联网的 Windows 10/11 电脑，用于第一次部署和生成 EXE。
3. 在部署电脑安装 Node.js LTS：打开 <https://nodejs.org/>，下载 LTS 版本，按默认选项安装。
4. 在部署电脑安装 .NET 8 SDK：打开 <https://dotnet.microsoft.com/download/dotnet/8.0>，下载 Windows x64 SDK，按默认选项安装。
5. 每间教室的 Windows 10/11 电脑能正常访问 HTTPS 网站。无需公网 IP，无需修改校园路由器，也无需开放入站端口。

## 二、第一次部署云端

### 1. 注册 Cloudflare

1. 打开 <https://dash.cloudflare.com/sign-up>。
2. 输入邮箱和密码完成注册及邮箱验证。
3. 免费套餐即可开始使用，不需要购买域名。

### 2. 运行一键部署

1. 打开本项目文件夹。
2. 双击 `deploy-cloud.bat`。
3. 黑色窗口会自动安装部署工具，然后浏览器会打开 Cloudflare 设备授权页面，并在窗口显示一个短设备码。
4. 在浏览器登录刚才注册的账号，输入设备码并点击允许 Wrangler 使用该账号。设备码约 5 分钟有效。
5. 回到黑色窗口，脚本会自动创建 D1 数据库、建立数据表、生成初始化密钥并部署网站。
6. 最后记下两项内容：`System URL` 是教师和教室端都使用的网址；`First-login initialization secret` 是仅第一次初始化 `ICe` 使用的密钥。

部署成功后，脚本会自动打开系统网址，并把网址保存到 `dist\delivery\cloud-url.txt`，供下一步生成交付包使用。

不要把初始化密钥发给教师。它只用于系统内还没有任何账号时创建固定最高管理员 `ICe`。

### 3. 初始化最高管理员

1. 在浏览器打开脚本显示的 `System URL`。
2. 页面显示“初始化最高管理员”，用户名固定为 `ICe`，不能修改。
3. 输入脚本显示的初始化密钥。
4. 设置 `ICe` 的登录密码。密码至少 10 位，同时包含字母和数字。
5. 完成后，用用户名 `ICe` 和刚设置的密码登录。

## 三、ICe 第一次配置学校使用数据

### 1. 创建班级

进入“班级管理”。如果学校是高中三个年级、每个年级约 20 个班，直接点击“**一键创建高中60班**”并确认一次即可。系统会自动创建高一、高二、高三各 1 至 20 班，已存在的班级会自动跳过。

系统不会预置学校名称或班级，由 `ICe` 自己创建。只需要一部分班级时，可以继续使用原来的“批量创建”功能。

- 单个创建：点击“创建班级”，输入 `高一（1）班`。
- 批量创建：点击“批量创建”，选择“高一”，起始班号填 `1`，结束班号填 `20`。高二、高三重复操作即可。
- 改名：在班级行点击“改名”。
- 停用：在班级行点击“停用”。停用不会删除历史记录。

只有 `ICe` 有创建、批量创建、改名和停用班级的权限，教师没有这些入口，接口也会拒绝教师操作。

### 2. 创建教师账号

1. 进入“教师管理”，点击“创建教师”。
2. 填登录用户名、教师姓名和初始密码。
3. 勾选该教师允许喊话的班级，可以同时选择多个班级。
4. 把系统网址、用户名和初始密码分别告知教师。

以后可在教师列表里重新分配班级、重置密码或停用账号。停用教师或重置密码后，该教师已有登录会话会退出。

教师数量没有程序内的人数上限，但实际容量仍受你自己的 Cloudflare 免费额度和平台规则约束。

## 四、生成教室电脑 EXE

1. 在项目根目录双击 `prepare-admin-package.bat`。
2. 脚本会自动构建 EXE 并生成 `dist\delivery` 交付包。
3. 如果需要单独构建，才运行 `build.bat`；如果需要单独生成交付包，才运行 `prepare-delivery.bat`。
4. 成品位于 `dist\receiver\ICeCreamShouter.exe`。

它是包含 .NET 运行环境的单文件程序，教室电脑不需要安装 Python、.NET 或其他依赖。第一次启动后，会在 EXE 同目录创建 `config.json`。因此请把 EXE 放在普通用户可写的目录，例如 `D:\ICeCreamShouter\ICeCreamShouter.exe`，不要放进可能禁止普通用户写文件的 `C:\Program Files`。

Windows 第一次运行自编译、未购买代码签名证书的 EXE 时，可能显示 Microsoft Defender SmartScreen。确认文件是你自己从本项目构建后，可点击“更多信息”再点击“仍要运行”。正式大规模分发时，购买代码签名证书可减少此提示。

### 交付包（推荐）

管理员电脑完成部署后，双击项目根目录的 `prepare-admin-package.bat`。脚本会自动构建并生成 `dist\delivery`：

- `教室端\ICeCreamShouter.exe` 和 `教室端\cloud-url.txt`：给每间教室复制这一整个文件夹；
- `教室端\一步使用说明.txt`：教室端只需双击 EXE，再输入一次绑定码；
- `教师端.url`：教师双击后直接打开网页；
- `cloud-url.txt` 和其他中文说明：由管理员留存。

教师和教室电脑不需要安装 Node.js、.NET、Python，也不需要运行 `build.bat`、`deploy-cloud.bat`、`prepare-admin-package.bat` 或 PowerShell。上述脚本只在管理员电脑上使用。

## 五、绑定每间教室电脑

每个班级都按下面步骤做一次：

1. `ICe` 登录网页，进入“班级管理”。
2. 在目标班级行点击“生成绑定码”。绑定码 15 分钟内有效，并且只能使用一次。
3. 把交付包中的 `教室端` 文件夹复制到该班教室电脑的固定目录并双击 EXE。
4. 如果使用 `prepare-delivery.bat` 生成的交付包，系统网址已自动预置，本机名称也会自动使用电脑名；窗口中只需输入一次性绑定码，保持“随 Windows 开机自动启动”勾选。
5. 如果没有交付包，才需要手动填写系统网址和本机名称。
6. 点击“绑定并开始接收”。成功后窗口关闭，右下角系统托盘出现接收端图标。
7. 右键托盘图标，点击“本机测试”，确认能看到全屏文字并听到 Windows 中文语音。

系统使用当前 Windows 用户的开机启动项。若教室电脑日常使用另一个 Windows 账号，应在实际日常账号下完成绑定和开机启动设置。

## 六、教师日常使用

1. 教师双击交付包中的 `教师端.url`；手机则在浏览器中打开同一网址并选择“添加到主屏幕”。
2. 输入 `ICe` 分配的教师用户名和密码。
3. 在“喊话台”选择目标班级。
4. 输入内容或点击快捷短语，选择提醒级别、语速和显示时间。
5. 点击“发送喊话”，再次核对班级和文字后确认。

页面会显示实际状态：教室离线、已发往教室、教室已收到、正在展示或处理失败。教室离线时，本条不会在恢复网络后补播。新喊话到达时会立即中断上一条显示和语音，以最新喊话为准。

通知声音规则：普通通知只在右下角静音显示；重要通知显示顶部横幅并播放声音；紧急通知全屏显示并播放声音。语音喊话只能选择重要或紧急，切换到语音模式时网页会自动选择重要。

### 公共禁言时间表

`ICe` 可在“禁言时间”页面添加每周公共时段，填写名称、开始时间、结束时间和星期后保存。所有教师都能查看，只有 `ICe` 能修改，时间统一按北京时间计算。

禁言时段内点击发送，网页会提醒当前正在上课。教师选择取消后，教室端不会显示也不会播放；教师选择“仍然发送”后，消息会正常送达。它是公共提醒，不是强制禁止，由班主任根据现场情况决定。

## 七、历史、密码和设备管理

- “历史记录”可按班级筛选，并导出 CSV。默认不自动删除。需要自动清理时，可把 `wrangler.toml` 的 `HISTORY_DAYS` 改为 30 至 3650 之间的天数后重新部署。
- 教师可把目标班级保存在书签中：在系统网址后添加 `?class=高一（1）班`。登录后若该教师有此班权限，会自动选中该班。
- “账号与设备”可修改当前账号密码。修改后所有浏览器会退出，再用新密码登录。
- `ICe` 在“账号与设备”中还能看到已绑定的教室电脑。教室电脑遗失、更换或绑定错误时，应停用旧设备；系统会立即断开它。
- 若新电脑要接替旧电脑：先停用旧设备，再为该班生成新的绑定码并绑定新电脑。

设置 `HISTORY_DAYS` 后的历史自动过期属于不可恢复的删除操作。启用前应先导出重要 CSV，并确认保留天数符合学校要求；保持 `0` 则不自动删除。

## 八、常见问题

### 教室端显示“连接中断，正在自动重连”

1. 先用浏览器打开系统网址，确认校园网络能访问。
2. 检查系统网址是否完整且以 `https://` 开头。
3. 在网页“账号与设备”确认该设备没有被停用。
4. 若设备配置已失效，重新生成绑定码，单击托盘雪花打开绑定设置并输入新码。
5. 查看日志：`%LOCALAPPDATA%\CloudRemoteShouter\logs\receiver.log`。日志不记录设备令牌或喊话正文。

### 有弹窗但没有声音

先确认通知级别。“普通”按设计就是静音弹窗，只有“重要”和“紧急”会播放声音。如果重要或紧急没有声音，再检查：

1. 检查 Windows 音量和当前输出设备。
2. 打开 Windows“设置”中的语音功能，确认安装了中文语音包。
3. 使用托盘菜单的“本机测试”。

### 教师看不到某个班级

`ICe` 进入“教师管理”，点击该教师的“分配班级”，勾选目标班级并保存；同时确认班级未被停用。

### 重新部署时数据库创建提示已存在

正常情况下，`wrangler.toml` 已保存数据库 ID，脚本会跳过创建。如果文件仍是 `REPLACE_WITH_D1_DATABASE_ID`，登录 Cloudflare 控制台，进入 Workers & Pages -> D1 SQL database -> `cloud-remote-shouter`，复制数据库 ID，替换 `wrangler.toml` 中的占位内容，再次运行 `deploy-cloud.bat`。

## 九、备份与费用说明

- 云端数据位于你自己的 Cloudflare D1 数据库。重要历史应定期从网页导出 CSV。
- 当前架构针对约 60 个班级、普通学校喊话频率设计，优先使用 Cloudflare 免费额度，但不能承诺任何第三方平台永久免费。
- 应定期登录 Cloudflare 控制台查看 Workers、D1 和 Durable Objects 用量。超出免费额度前，Cloudflare 的实际处理方式以你的账号套餐和当时平台规则为准。
- 不要在公开群聊发送 `ICe` 密码、教师密码、初始化密钥或教室 `config.json`。
